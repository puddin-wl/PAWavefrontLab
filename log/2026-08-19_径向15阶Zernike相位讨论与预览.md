# 2026-08-19 径向 15 阶 Zernike 相位讨论与预览记录

## 1. 本次目标与当前结论

本次讨论的目标是提高已知 SLM 随机调制相位的 Zernike 阶数，并先观察高阶
相位的形态，再决定是否投入 NeuWS 闭环仿真。

当前选择为：

- 最高径向阶数：`n = 15`；
- 完整 Noll 范围：`1–136`；
- 禁用项：Noll `2、3`（两个方向的 Tilt）；
- 保留项：Noll `1`（Piston）以及 Noll `4–136`；
- 有效随机模式数：`134`；
- 系数分布：各有效模式独立高斯分布；
- 单项标准差：`1.22 rad`；
- 随机种子：`20260731`；
- 相位约定：NeuWS 使用 `exp(-1j * proj_sim)`。

目前只生成了 3 组相位用于观察外观，**尚未生成调制测量、尚未送入 NeuWS
网络训练，也尚未完成闭环重建和评价**。

## 2. 径向阶数与 Noll 编号的对应

完整包含到径向阶数 `n` 时，模式总数和最高 Noll 编号为：

```text
J_max = (n + 1) (n + 2) / 2
```

因此径向 15 阶对应：

```text
J_max = (15 + 1) (15 + 2) / 2 = 136
```

讨论中列出的常用对应关系如下：

| 最高径向阶数 | 完整 Noll 范围 | 模式总数 |
| ---: | ---: | ---: |
| 6 | 1–28 | 28 |
| 7 | 1–36 | 36 |
| 8 | 1–45 | 45 |
| 9 | 1–55 | 55 |
| 10 | 1–66 | 66 |
| 11 | 1–78 | 78 |
| 12 | 1–91 | 91 |
| 13 | 1–105 | 105 |
| 14 | 1–120 | 120 |
| 15 | 1–136 | 136 |
| 16 | 1–153 | 153 |
| 17 | 1–171 | 171 |
| 18 | 1–190 | 190 |
| 19 | 1–210 | 210 |
| 20 | 1–231 | 231 |

这里必须区分“径向 15 阶”和“Noll 15”：Noll 15 只完整覆盖到径向阶数
`n = 4`，而径向 15 阶需要 Noll `1–136`。

## 3. 项目原有阶数设置

检查 PAWavefrontLab 后确认存在几套不同用途的设置：

- 真实实验双网格 SLM 生成器 `tools/generate_dual_grid_slm.py`：原来固定使用
  Noll `1–10`，并将 Noll `2、3` 置零；最高径向阶数为 `n = 3`。
- 完整静态仿真工作流：SLM 默认使用 Noll `1–15`，即最高径向阶数
  `n = 4`。
- 系统像差和单图像差工具：使用 28 项系数容器，即 Noll `1–28`，最高径向
  阶数 `n = 6`；默认静态系统像差实际只有 Noll `4–15` 非零。
- 网络原始空间特征使用 28 项 AOtools Zernike 特征。这是原有网络配置，不是
  AOtools 基函数生成能力的硬上限。

AOtools 的 `zernikeArray` 没有在项目中写死最高 Noll 编号。已验证
`256×256` 下 Noll `1–200` 可以生成且结果有限；继续提高时主要受内存、计算量
和空间采样质量约束，而不是 `28` 这个数值约束。

## 4. 为什么将标准差从 5 rad 调整为 1.22 rad

原真实实验生成器有 10 个系数，其中 Noll 2、3 被置零，因此约有 8 个有效
随机模式，每项标准差为 `5 rad`。如果把 134 个有效模式仍全部设为
`5 rad`，总相位 RMS 会随模式数的平方根显著增加，所得相位会远强于原调制。

为大致保持原调制的总随机强度，本次采用：

```text
sigma_new = 5 * sqrt(8 / 134) ≈ 1.22 rad
```

这只是“保持总 RMS 量级”的对照方案，并不代表唯一或最优的物理分布。正式
实验还可以按径向阶数衰减高阶系数，而不是让所有模式使用完全相同的标准差。

## 8. 尚未执行的工作与建议顺序

目前没有把本次 15 阶相位放入前向模型或网络。正式验证建议按以下顺序进行：

1. 将双网格 SLM 生成器改成可配置的最高径向阶数，并采用低内存逐模式或分块
   生成，避免 1080 网格一次性保存 136 项完整基函数。
2. 使用径向 15 阶、Noll `1–136`、Noll 2/3 置零、`sigma=1.22 rad` 生成完整
   50 帧，保存到新的数据目录，不能覆盖已有的 Noll 1–10 实验数据。
3. 使用 `data/test.tif` 和一份固定系统像差生成对应的 50 张调制测量。
4. 将 50 组 `SLM_simN.mat` 与 `SLM_rawN.mat` 送入 NeuWS 网络训练。
5. 与原低阶 SLM 方案比较物体 PSNR/SSIM、系统像差相位 RMSE、收敛速度和稳定性。

在完成上述 50 帧闭环之前，当前结果只能说明“径向 15 阶相位能够正确生成并
观察”，不能说明它一定会提升 NeuWS 重建质量。

## 9. 测试入口统一为 pytest

本次检查发现项目测试同时包含两种写法：大部分测试继承
`unittest.TestCase`，而 `tests/test_bin_to_tiff.py` 使用 pytest 的函数、
`tmp_path` 和 `pytest.raises`。原 README 推荐的 `unittest discover` 会导致
BIN/TIFF 测试无法被正确收集，因此将统一测试入口改为 pytest，同时保留现有
`unittest.TestCase` 测试，不做无关重写。

已完成：

- 在 `neuws` Conda 环境安装 pytest `9.1.1`；
- 在 `requirements.txt` 中加入 `pytest>=8,<10`；
- 将 README 的完整测试命令更新为 `python -m pytest -q`；
- 将可选的 `1000×1000` CUDA 验收测试更新为 pytest 的精确测试路径。

实际运行命令：

```bash
/home/xiangwan/miniconda3/envs/neuws/bin/python -m pytest -q
```

实际结果：

```text
25 passed, 1 skipped, 1659 warnings in 42.70s
```

其中 25 项 CPU 测试全部通过，包括此前未由 `unittest discover` 正确执行的
6 项 BIN/TIFF 测试。跳过项是需要显卡设备的 `1000×1000` CUDA 前向与反向
验收测试；本次 Codex 沙箱未暴露 `/dev/nvidia*`，因此
`torch.cuda.is_available()` 为 `False`。这表示当前沙箱没有 GPU 设备权限，
不表示宿主 WSL 的 CUDA 或 PyTorch 安装损坏。

警告主要来自 AOtools 1.0.7 使用 NumPy/SciPy 已弃用接口，以及完全相同图像的
PSNR 为无穷大时 scikit-image 产生的除零提示；当前均未造成测试失败。依赖
一致性检查 `python -m pip check` 也已通过。
