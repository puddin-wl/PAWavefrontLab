# 2026-08-31 去相关去噪 GPU 并行加速构想

## 背景

当前电机串扰去相关程序按 BIN 文件逐份处理，并在单帧内部按图像行分块读取
`900×900×512` packed-12 光声数据。每个分块对所有 A-line 执行模板归一化
互相关、滑动信号能量、最佳匹配位置选择、有效重叠区最小二乘幅度拟合和模板
扣除。

主要计算量来自 `preprocessing/pa_denoising.py` 中的两次 FFT 卷积：

- A-line 与 361 点模板的滑动点积；
- A-line 平方值与 361 点全一核的滑动能量。

这些运算在 A-line 之间完全独立，适合并行计算。

## 可行的两级加速

### 1. 帧级 CPU 并行

- 不同 BIN 文件彼此独立，可使用 2 个工作进程并行处理；
- 每个进程继续采用当前流式读取与分块算法；
- 不建议直接启动过多进程，因为原始文件每份约 622 MB，容易受 Windows C 盘
  读取速度、内存带宽和临时数组占用限制；
- 先对 1、2、4 个进程做端到端计时，再决定默认并发数。

### 2. CuPy 或 PyTorch CUDA 单帧加速

- CPU 继续负责 packed-12 流式读取和解码；
- 每次向 GPU 传输约 20–50 行 A-line，而不是一次加载完整三维体数据；
- GPU 负责 FFT 卷积、NCC、幅度门控、最佳中心选择和模板扣除；
- 每个分块只把二维投影与相关性诊断结果传回 CPU；
- 当前环境没有安装 CuPy，但已有 CUDA PyTorch 和 Numba。实现时应同时评估
  CuPy 的 `cupyx.scipy.signal` 路线与现有 PyTorch CUDA 路线，优先选择依赖更少、
  与 CPU 结果更容易保持一致的方案。

单卡上不建议同时把 50 帧全部提交到 GPU；更合适的是流式单卡流水处理。

## 必须满足的数值等价性

GPU 版本不能只比较最终图片外观。必须与当前 CPU 正式实现逐级核对：

- packed-12 解码逐值一致；
- 滑动点积、模板能量、NCC 和拟合系数在规定容差内一致；
- 中心和边缘截断模板测试均通过；
- 正负模板、低能量门控和非法参数测试均通过；
- 对 NCC 接近 `0.70`、拟合峰值接近 `80 ADC` 的边界样本重点检查；
- 最终 `matched_map`、`center_map`、去噪 MIP 和 shared-max 训练输入与 CPU 版
  逐项比较；
- 至少选一份完整 900×900 BIN 做 CPU/GPU 正式对照并记录耗时、峰值内存和
  不一致像素比例。

浮点 FFT 的微小误差可能让阈值附近的少量 A-line 改变接受/拒绝判定。因此，
在完成上述验收前，GPU 版本不能替换正式数据处理路径。

## 本次决定

2026-08-31 的径向 4 阶真实采集仍使用已经验证过的 CPU 去相关实现。本轮不安装
CuPy、不修改正式算法，也不把 GPU 加速实验与系统像差恢复结果混在一起。GPU
并行化作为后续独立任务处理。
